# Spécification Technique 04h : Paramétrage Audio/Vocal et Synthèse IA des Réunions

**Date** : 2026-10-07  
**Auteur** : Lead Solution Architect  
**Statut** : Validé  
**Périmètre** : Traitement des incohérences de Priorité 3 (**INC-07** et **INC-08**) issues de l'audit architectural.

---

## 1. Contexte & Objectifs

L'audit architectural a mis en lumière deux incohérences ergonomiques et fonctionnelles sur le volet audio/productivité :
1. **INC-07 (Pipeline Vocal)** : Absence de configuration des modèles STT (Whisper) et TTS (Piper), et impossibilité dans l'interface utilisateur de sélectionner les périphériques micro/haut-parleur parmi ceux détectés par `list_audio_devices`.
2. **INC-08 (Comptes-rendus de Réunion)** : Lors de l'arrêt d'un enregistrement (`stop_meeting_recording`), la note Markdown générée contient la diarisation brute et les captures de diapositives, mais aucune synthèse exécutive, décisions clés ou tâches à mener (Action Items) ne sont dérivées par l'IA, alors que le moteur d'inférence est disponible.

Cette spécification définit l'architecture de remédiation, les structures de données, l'IPC Tauri et les tests d'acceptation requis.

---

## 2. Spécification Détaillée des Évolutions

### 2.1 INC-07 : Configuration Vocale & Sélection des Périphériques Audio

#### 2.1.1 `crates/core/src/voice.rs`
1. Création de la structure `VoiceConfig` :
   ```rust
   #[derive(Debug, Clone, Serialize, Deserialize, PartialEq, Default)]
   pub struct VoiceConfig {
       pub whisper_model_path: Option<String>,
       pub piper_model_path: Option<String>,
       pub selected_input_device: Option<String>,
       pub selected_output_device: Option<String>,
       pub remote_stt_endpoint: Option<String>,
   }
   ```
2. Mise à jour de `VoicePipeline` :
   - Ajout d'un champ thread-safe `config: Arc<tokio::sync::Mutex<VoiceConfig>>`.
   - Méthodes publiques `get_config(&self) -> VoiceConfig` et `update_config(&self, config: VoiceConfig)`.
   - Mise à jour de `WhisperSttEngine` et `PiperTtsEngine` pour refléter les chemins de modèles configurés.

#### 2.1.2 Backend Desktop (`apps/desktop/src-tauri/src/lib.rs`)
1. Nouvelles commandes Tauri IPC :
   - `get_voice_config(state)` -> `Result<VoiceConfig, String>`
   - `update_voice_config(state, config)` -> `Result<VoiceConfig, String>`
   - Persistance dans `.jeanne/voice_settings.json` au sein du vault (ou fallback local).
2. Déclaration des permissions TOML pour les deux nouvelles commandes dans `apps/desktop/src-tauri/permissions/autogenerated/` et inclusion dans `capabilities/default.json`.

#### 2.1.3 Interface Utilisateur (`apps/desktop/src/App.svelte` & IPC types)
1. Ajout des types TypeScript dans `types/ipc.ts` : `VoiceConfig`.
2. Dans la section Vocale du Dashboard / Paramètres :
   - Menus déroulants `<select>` pour choisir le microphone parmi `audioDevices.input_devices` et la sortie audio parmi `audioDevices.output_devices`.
   - Champs de saisie optionnels pour le modèle Whisper (`.bin`) et le modèle Piper (`.onnx`).
   - Bouton de sauvegarde et persistance réactive.

---

### 2.2 INC-08 : Synthèse IA Automatique des Réunions

#### 2.2.1 `crates/core/src/meeting.rs`
1. Enrichissement de `MeetingNoteGenerator` :
   ```rust
   pub fn build_meeting_summary_prompt(session: &MeetingSession) -> String
   pub fn inject_ai_summary_into_note(raw_markdown: &str, summary_content: &str) -> String
   ```
2. Le prompt de synthèse demande formellement :
   - Un résumé exécutif (3 à 5 phrases).
   - Les décisions clés adoptées.
   - Les actions à mener (ToDo au format `- [ ] Tâche`).

#### 2.2.2 Backend Desktop (`apps/desktop/src-tauri/src/lib.rs` - `stop_meeting_recording`)
1. Après `self.meeting_recorder.stop_recording()`, si le moteur d'inférence est prêt (`state.local_engine.is_inference_ready().await`) et que des segments vocaux existent :
   - Construction du prompt via `build_meeting_summary_prompt`.
   - Appel à `state.local_engine.generate_stream(prompt, cancel)`.
   - Injection automatique de la synthèse dans le fichier Markdown de la note générée.
2. Si le moteur n'est pas prêt ou en mode autonome, injection d'une synthèse par défaut élégante basée sur les locuteurs détectés.

## 3. Plan de Test & Critères d'Acceptation

1. **Test unitaire VoiceConfig** : Sérialisation, désérialisation et mise à jour dynamique du pipeline.
2. **Test unitaire Synthèse Réunion** : Construction du prompt, injection du résumé Markdown sans altération du frontmatter.
3. **Contrôle d'intégrité Tauri** : `just check-permissions` (linter IPC) à 100% vert (40 commandes avec les 2 nouvelles).
4. **Validation globale** : `just pre-review` (0 warning clippy, tous tests réussis, build Vite OK).
